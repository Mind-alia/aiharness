# Workspace IA pitfall registry

This registry lists the pitfalls, regressions and technical traps encountered during multi-agent work sessions. It serves as the project's collective memory so that the same mistakes are not repeated.

This document is automatically re-injected into the common instruction passed to every agent by the delegation script (`scripts/delegate.sh`). In keeping with the kit's continuous-improvement principle, every bug or malfunction discovered after delivery must lead to the immediate addition of a new row to this table.

| Pitfall | Symptom | Countermeasure | Source |
|---|---|---|---|
| Invented or unsupported command options or packages | System commands fail or false bugs are reported in the documentation because of options incompatible with Debian. | Require systematic verification of each option in the documentation of the exact installed version (e.g. Debian Bookworm). | Inception |
| Exit code of a verification masked by a filter | `npm test \| tail -20` or `... \| grep` returns the filter's exit code: a failure passes for a success and a broken commit is validated. | Run verifications with `set -o pipefail`, or write the output to a file then read the exit code before displaying an excerpt. | Codex review, 17/10 |
| Unbounded wait loop (`until … sleep`) in an agent command | Past the tool's timeout, Claude Code moves the command to the background instead of killing it; if the condition never arrives (expected journal never written, `timeout` missing on macOS, suite relaunched another way), the loop runs for hours after the factory run ends. No tokens consumed, but ghost processes and a misleading task list. | Bound every wait (`for i in $(seq 1 N); do … ; sleep 10; done` then exit with an error), never wait for a file you have not seen created, and check when releasing the lock that no shell of the session survives. | Pole 8 and Pole 9, 19/10; a second user |
| Executor that rummages through the host | `git log`, `git branch`, `cd`, `sed -i` run on the host outside the container, reading of the main repository, plugins loaded from `~/.codex`: the agent process stays on the host, no key entering the container. | `executor` hook of `hooks_guard.py` (only `bash scripts/run-in-sandbox.sh` and `bash scripts/ask.sh`, a simple command, worktree files) and a reduced `CODEX_HOME` for Codex. What is missing is requested with `bash scripts/ask.sh "<question>"`; a refused command is not retried in another form. | E11, 22/10 |
| Writing to the worktree from the container | `Read-only file system` on `/work`: a task's container mounts the worktree read-only (a link created from the container would be followed by the host's tools). | Write and modify with Edit/Write; only `.workspace/` and, in node, `dist`, `coverage`, `test-results`, `playwright-report` are writable in the container, in memory, invisible to the host. | T65, 22/10 |
