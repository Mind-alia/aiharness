# Housekeeping — where files go, how they are named, how they retire

Single housekeeping rule set for the kit, the console and every adopted project. Read it before creating, moving, renaming or
removing a document, and at the end of every session (checklist at the bottom). Written on 26 October 2026 after the big tidy-up
(`docs/LOG.md`, entries of that day).

## 1. Principles (taken from projects that keep their docs alive)

- **One owner per fact.** Each fact lives in exactly one file; every other file links to it instead of restating it. The owner tables
  are in each repository's `AGENTS.md`. A second copy of a rule is a future contradiction.
- **Minimum viable documentation** (Google documentation guide): a short, true document beats a long, stale one. Delete or archive
  dead documentation in the same change that makes it dead; update the docs in the same commit as the code they describe.
- **Know what kind of document you write** (Diátaxis): a rule or instruction (`AGENTS.md`, `docs/ORCHESTRATEUR.md`), a reference
  (`docs/MAP.md`, templates), a record of state (`STATUS`, `TRAVAUX`, `QUESTIONS`), or history (`LOG`, journal, decisions). Never mix
  history into a rule file: a rule file says what is true now, the history file says how it came to be.
- **Decisions are records** (ADR practice): written once with their date, never rewritten; a later decision supersedes an earlier
  one by a new dated line, and the older text elsewhere is corrected in the same change.
- **Docs as code:** links are checked by `scripts/docs-check.sh` in the gate; a document that fails the check is a failing test.
- **Generated files are never edited by hand** (`.claude/agents/*.md` come from `team.json` via `workspace team-agents`).

## 2. Where each kind of file lives

| Kind | Kit | Console (and adopted projects) |
|---|---|---|
| Rules for agents | `AGENTS.md` (≤ 80 lines) | `AGENTS.md`, `CODEX.md` |
| Orchestration instructions | `docs/ORCHESTRATEUR.md` (one file for every project) | the kit's file, never a local copy |
| Housekeeping | this file | this file |
| Current state | `docs/TRAVAUX.md`, `docs/QUESTIONS.md` | `docs/STATUS.md`, `docs/MAP.md`, `docs/QUESTIONS.md` |
| History (append only) | `docs/LOG.md` | `docs/LOG.md`, `CHANGELOG.md`, `docs/decisions.md`, `docs/adr/` |
| Dated plans and reports | `docs/journal/<YYYY-MM-DD>/` | `docs/journal/` |
| Studies: protocol and results | `docs/research/` (in Git) | — |
| Studies: raw data (logs, clones, diffs, branch bundles) | `Workspace-IA/etudes/<study>/`, index `etudes/README.md` (outside Git) | same |
| Attack benches | `docs/security/` | — |
| Obsolete but worth keeping | `docs/archive/` | `docs/archive/` |
| Worthless | `~/Workspace-IA/trash/` with `TRASH.md`, outside every repository | same |
| Caches, logs, build output | ignored by `.gitignore`, never committed, regenerated by the tools | same |

Nothing else at the root of a `docs/` folder: a new kind of document needs a row in the owner table of `AGENTS.md` first.

## 3. Names

- Dates in ISO 8601: `YYYY-MM-DD`, in folder names (`docs/journal/2026-10-26/`) or as a prefix (`2026-10-25-veille-harnais.md`).
- A study's files carry the study id: `E13-PREENREGISTREMENT.md`, `E13-RESULTATS.md`; its raw data goes in `etudes/E13/`.
- Plans and reports: `PLAN-JOUR-<date>[-topic].md`, `RAPPORT-JOUR-<date>[-topic].md`, always inside `docs/journal/<date>/`, never at the root of `docs/`.
- ASCII, no spaces, hyphens between words. Existing French file names (`PIEGES.md`, `FICHE-TACHE.md`, `ORCHESTRATEUR.md`, `TRAVAUX.md`…)
  stay: code and tests read them by name. Renaming one is a circuit task with its tests.

## 4. Language

Agent instructions in English; the owner's records (`TRAVAUX`, `QUESTIONS`, `LOG`, `decisions`, journal, research) in French;
always answer the owner in French. Tokens parsed by code stay verbatim whatever the language around them (`vraie`, `fausse`,
`non_verifiable`, task-sheet headings until T92, report header lines).

## 5. Lifecycle of a document

1. **Living**: listed in an owner table or linked from `docs/MAP.md`.
2. **Superseded**: the newer document exists. In the same change, either fold what is still true into the owner file and retire
   the old one, or add one line at its top: `Superseded on <date> by <file>`.
3. **Retire**: before moving or removing, search the whole repository *including code and tests*
   (`git grep -n <file name>`): if code or a test reads it, it stays until a circuit task changes that code. Otherwise `git mv` it to
   `docs/journal/<date>/` (a dated plan or report), `docs/archive/` (worth keeping), or the trash (worthless; Git history keeps a copy).
   Fix every link that pointed to it, then run `bash scripts/docs-check.sh`. Old mentions inside `docs/LOG.md` stay untouched: they are history.
4. **Trash**: outside the repositories, one `TRASH.md` saying origin and reason for each item. Only the owner empties it.

## 6. Contradictions

- The latest dated decision wins (`docs/QUESTIONS.md`, console `docs/decisions.md`, then `docs/LOG.md`). Correct the older text in
  the same change; never leave two rules that disagree.
- A contradiction that no dated decision settles is a question for the owner (`docs/QUESTIONS.md`), not a guess.
- Search for contradictions after any change to a rule: `git grep -n` the key words of the rule in every living document.

## 7. Removing things safely

- Absolute paths only; never `cd … && rm`; list the target in the same command before touching it.
- The agent moves things to the trash; the owner deletes. Branches: `git bundle create` and `git bundle verify` before `git branch -D`,
  bundle kept in the trash or with the study it belongs to. Never delete a remote branch or push without the owner's request.
- Temporary work goes in a session scratchpad or `/private/tmp`, never inside a repository, and is cleaned at the end of the session.

## 8. End-of-session checklist

1. `git status` clean in every repository touched; nothing left uncommitted without saying so.
2. `bash scripts/docs-check.sh` exit 0 in every repository touched.
3. No new file at the root of a `docs/` folder outside the owner table; no plan or report outside `docs/journal/`.
4. No worktree, clone or log left in `/private/tmp` or `~/.workspace-ia/work` (`git worktree list` shows one line per repository).
5. Every rule changed today: contradictions searched (section 6).
6. Every file retired today: references searched including code, links fixed, reason written (`TRASH.md` or the commit message).
7. One entry in `docs/LOG.md` for the session's changes.
